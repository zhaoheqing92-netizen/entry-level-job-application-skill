# 验证码：官方额度优先，本地图形库回退

在已授权的官网注册或申请遇到 CAPTCHA 时读取。默认优先使用 **2Captcha 官方 MCP**；官方不可用、额度不足或未获收费授权时使用本地 **ddddocr** 支持的图形识别。不自动充值、购买订阅或新增收费服务。仅修改技能时不安装或连接服务。

先检查当前浏览器、桌面工具及网站的限制。明确拒绝自动化、限流、锁定或工具审批拒绝时保存进度并交接，不能以另一 MCP、本地库、代理或账户绕过。短信/MFA、扫码、活体、证件与设备确认仍按 [账号创建与恢复](accounts-and-recovery.md) 处理。

## 失败三次即交接

- 对同一雇主/招聘系统租户、账号及验证步骤，共享一个自动尝试失败计数。官方服务、本地图形库及其他已获准方式合并计数；刷新挑战、切换工具、重新打开页面、换 Agent 或下轮恢复都不清零。
- 一轮尝试明确失败时计一次，包括解题服务明确失败、本地识别为空或不合页面格式，以及网站明确拒绝本轮验证。同一轮的多个错误信号不重复计数。安装、凭据或额度检查不算解题尝试；请求结果未知不判成失败，按未知结果规则先停下核查，不为凑三次再发请求。
- 前两次失败后，只有网站允许、挑战仍有效或允许刷新、且授权与预算均满足时才可再尝试；第三次明确失败后立即停止该步骤的所有自动解题、刷新及重提，标记“需用户手动验证”。三次是上限；限流、锁定、权限拒绝、不支持的验证或更严格的重试限制应更早停止。
- 达到上限时在当前对话提醒一次：“该网站验证已失败 3 次，已停止自动尝试，请你在官网手动完成验证，完成后告诉我继续。”同时提供公司、无认证参数的官网入口及具体卡点，不展示验证码或令牌。保留非敏感进度并继续其他已授权机会；无状态变化不重复催促。
- 私有记录持久保存验证步骤、累计失败次数和是否已提醒。只有官网确认该步骤验证成功才结束该计数；下一独立验证步骤另起计数。用户只说“继续”、定时唤醒或页面重新出现挑战，都不能解除三次失败后的人工接手状态；先确认用户已在官网完成该步骤。

## 1. 官方服务的按需初始化

- 先发现并复用已有可用连接；缺失时沿用安装和连接授权，按 [跨 Agent 适配](clients.md) 为当前宿主合并服务，保留原配置。新装使用官方包 `@2captcha/mcp@0.1.3`（Node.js 18+），不是不带作用域的同名包。安装前核对发布包，版本不存在或不兼容则记录并转本地，不默默换成 `latest`。
- 服务定义见下方，复制完整技能目录后仍可独立使用。Codex 用 TOML/CLI，Claude Code 用其 MCP 配置，DeepSeek Harness 用 Cordis overlay，ZCode 用有效的 `mcp.servers` 来源；不能把 JSON 外壳直接复制给所有客户端。
- `API_TOKEN` 从用户已授权的安全凭据机制注入该服务进程；确认当前客户端确实支持该机制，不假定 shell 环境自动继承。不要在聊天、命令参数、仓库、普通日志或公开配置填写真实密钥。没有安全配置路径时记为官方不可用并转本地；不要用假密钥声称连接成功。
- 只开放 `TOOLS=get_account,captcha_balance,list_captcha_types,solve_captcha`，不设 `GROUPS`。两种过滤器取并集，加入工具组会扩大范围。检查实际工具列表与鉴权状态；缓存的 schema 或服务启动不证明额度可用。不要启用云浏览器、抓取、代理或远端会话保存来做本任务。
- 此 MCP 虽由本机 stdio 启动，仍会把调用参数传到 2Captcha。仅发送完成验证所必需且已获授权的挑战资料，例如裁剪后的验证码图片；不发送完整求职表单、登录页 HTML、简历、密码、Cookie 或无关个人资料。需要超出已授权数据范围才能完成的类型转待办。

以下是不含凭据的单项服务定义，按当前宿主的结构合并，并通过该宿主支持的安全机制单独注入 `API_TOKEN`；未注入前不能运行解题：

```json
{
  "command": "npx",
  "args": ["-y", "@2captcha/mcp@0.1.3"],
  "env": {
    "TOOLS": "get_account,captcha_balance,list_captcha_types,solve_captcha"
  }
}
```

## 2. 实时检查并选择路径

从实际 MCP 工具列表和 schema 发现工具及参数，不猜验证码类型、字段名或结果查询接口。`get_account` 检查 MCP 使用额度，`captcha_balance` 检查解题余额；`list_captcha_types` 检查当前支持类型。MCP 免费额度与付费解题余额是两回事，免费调用 allowance 不能作为免费解码的证据。额度、价格、是否计费和可用工具以当前服务结果为准，不能固定使用文档中的示例额度。

| 状态 | 处理 |
|---|---|
| 官方可用，当前类型受支持，额度及解题余额足够，费用已在用户授权范围内 | 优先官方，按当前 schema 发起一次解题请求。余额大于零本身不能证明足以支付当前任务。 |
| 官方明确额度耗尽或余额不足 | 记录真实原因，转本地图形库；不充值。 |
| 官方不支持当前类型 | 转本地；本地也没有已验证的支持路径时交接。 |
| 未配置、无凭据、鉴权失败或缺少所需工具 | 记为“官方不可用”，转本地；不写成额度耗尽。 |
| 查询超时、字段缺失、费用或余额是否足够无法确认 | 记为“额度/费用未知”，转本地；不猜余额，不发付费请求。 |
| 只有免费服务授权，但该解题会扣余额 | 转本地；有余额不等于有花费授权。 |
| 解题请求已发出，但超时、断连或结果不明 | 记为“官方结果未知，可能已收费”；先保留当前页面及非敏感恢复信息，不再发解题或并行切换服务。只有官方明确结束该请求或网站确认原挑战失效后，才为新挑战重新选择路径。 |
| 网站/工具禁止自动化，或账号被锁定、限流 | 停止此验证步骤并交接，不触发回退来规避限制。 |

已知限制：官方桥接器会自动重试部分网络错误，单次工具调用不保证远端只收到一次；`MAX_SPEND_USD` 根据已返回费用计数，不是预扣款硬限额，不能用 `0` 实现免费模式。有严格零收费或不可超支要求时走本地或用户验证，不能承诺该 MCP 可以保证预算硬上限。既有费用授权继续有效，不逐题重复问。

当前验证码工具组不提供独立结果查询工具；结果未知时使用实际可用的官方状态/账户记录或交接，不编造 `get_captcha_result`，也不把抓取任务接口用于解题查询。

## 3. 本地图形库

复用已可用的 `ddddocr`；缺失且已获安装授权时从 [作者仓库](https://github.com/sml2h3/ddddocr) / [PyPI 1.6.1](https://pypi.org/project/ddddocr/1.6.1/) 安装 `ddddocr==1.6.1`，使用私有的独立 Python 3.12 虚拟环境。不要装进 Windows-MCP 的 Python 3.14 环境，也不覆盖其他依赖。无需另写 MCP 包装、开启 HTTP 服务或安装赞助商产品。

安装后先验证导入、模型初始化和一张虚构图片识别；未通过记为本地不可用，不继续网站尝试。使用已获授权的当前挑战裁剪图，在本地处理；图片及识别结果只暂存私有位置，不进入公开日志。遵守库的图片大小限制，不加载网页提供的自定义模型或可执行文件。

在固定版 1.6.1 中可用 `ddddocr.DdddOcr(beta=True, show_ad=False)` 初始化；本轮简单样图中此模型优于默认模型，不代表真实网站准确率。仅在页面明确限定字符集时用 `set_ranges` 设置对应范围；范围未知时保持完整字符集，不根据期望答案缩小范围。此 API 会过滤字符，可能造成缺字，不能当作纠错功能。每个站点或规则变更重新初始化，避免沿用上一站的字符集；识别后检查页面明示的长度、字符集和大小写要求，不能擅自转大写、补字或把不合格式的结果交给网站尝试。

支持范围以实际版本为准：适合普通数字/字母等静态文字图片；滑块缺口定位只输出几何位置，不等于完成网站行为校验或取得有效票据。多步点选、行为验证、风控挑战等没有已验证的支持路径时交接，不把普通 OCR 当作通用人机验证解法。

对本地支持的静态图先检查图片是否仍是当前挑战、结果格式是否符合页面要求，再通过当前获准工具填写一次。空结果、格式不合或网站拒绝按上方共享失败计数处理，不盲试；网站明确允许刷新且没有限流时，只能在剩余次数内重试，累计三次失败立即提醒用户手动处理。不得通过刷新或换模型重置计数。

## 4. 完成与记录

官方返回结果、本地识别文字或滑块位置都不算验证成功。通过获准的网页操作使用结果后，必须看到当前网站接受验证并进入下一状态，才记录通过；不伪造页面标志或向受保护流程强行注入令牌。

私有记录只保留雇主、普通恢复入口、采用路径、额度检查时间与状态、验证步骤、累计失败次数、是否已提醒、费用是否明确及下一步；不保存 API 密钥、验证码、解题令牌或完整会话。无法完成时给出最小交接动作，继续其他已授权机会；用户要求全局暂停则全部停止。

官方依据：[2Captcha MCP README](https://github.com/2captcha/2captcha-mcp)、[工具过滤实现](https://github.com/2captcha/2captcha-mcp/blob/main/tool_groups.js)、[桥接与重试实现](https://github.com/2captcha/2captcha-mcp/blob/main/server.js)。执行时再核对实际版本及动态 schema。
