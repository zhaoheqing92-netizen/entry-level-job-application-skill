# 参赛说明与演示

## 一句话介绍

让初级岗位求职者用一份简历开始，由 AI 核对官网岗位资格、填写有依据的申请，并在人工验证或网络中断后继续处理，减少重复填写和误投。

## 产品边界

交付的是可复用的求职 Skill、后台检查脚本和使用说明。用户用已有 Agent 执行；不是独立招聘平台，不出售雇主岗位或保录用服务。普通搜索直接进行，内部检查由 Agent 完成，缺少必要事实时才集中问用户。

## 四分钟演示

1. 30秒：给出一份虚构简历与目标，展示用户只需提供材料和授权。
2. 60秒：比较完整匹配、毕业届别不符、未写经验限制的三个岗位；解释硬条件不能被高分抵消，未写限制也不等于雇主保证接受。
3. 60秒：展示有来源的填写、附件语言检查，以及只选择必要条款。
4. 60秒：本人验证交接 → 核对页面 → 提交结果未知 → 先查记录；展示再次提交被阻止。
5. 30秒：展示真实测试结果和待验证范围。支付演示在完成平台接入后单独展示，不能用模拟“已支付”按钮替代。

运行 `python tools/demo.py --output evaluation/demo` 可生成离线 JSON 和 HTML。全部场景为合成数据，不访问官网，不代表实际投递或付费。正式演示使用真实用户数据前取得许可并隐藏个人资料。

## 支付宝 PAYATHON 对齐

截至2026-11-08，[官方赛事页](https://aipay.alipay.com/community/events/payathon-2026)列出的评审关注点是产品完整度、支付集成度、商业化表现和作品影响力，未见公开数值权重。报名截止12月1日，作品提交截止12月9日，线下决赛12月26日；以官网后续更新为准。

| 方向 | 当前可出示 | 仍需真实完成 |
|---|---|---|
| 产品完整度 | 可安装技能包、离线核查与恢复演示、公开测试 | 目标客户端和具体 ATS 的获准实测 |
| 支付集成度 | 完整打包工具；拟采用平台现成支付交付 | 商户准入、签约、真实支付与交付验收 |
| 商业化表现 | 明确用户问题与交付边界 | 真实付费、退款和用户留存，不能编造 |
| 作品影响力 | 开源仓库和可复现材料 | 获准公开的真实反馈、使用记录和改进证据 |

优先 [SkillPay](https://skillpay.alipay.com/) 现有买断交付，按[官方 FAQ](https://skillpay.alipay.com/faq)及[更新日志](https://skillpay.alipay.com/changelog)核查签约与下载。一次购买技能不授予求职数据权限。签约、收费或上架是独立外部动作；本次本地开发没有执行这些动作。

支付接入后只需验收五件事：未支付不授予付费交付；成功付款获得正确版本；取消不发货；支付后交付失败可恢复且不重复收费；退款/撤单按平台真实权益处理。测试交易与真实销售分开记录；不自买刷量，不把测试金额算收入。

## 下一轮用户验证

邀请少量自愿用户，限定一个已验证客户端和一种 ATS，记录：完成任务数/尝试数、错误字段数/已核对字段数、人工接管次数、用户实际花费时间、具体阻碍。保留失败案例；不要把本地用例通过率称为真实申请成功率，不把来源字符串齐全称为事实已认证。

已有开源作品的赛事资格、实际账号的商户资格和第三方市场交付兼容性尚需各平台确认。本仓库没有接入支付凭据，也不保证获奖。
